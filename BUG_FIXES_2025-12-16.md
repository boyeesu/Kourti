# Bug Fixes - December 16, 2025

## Summary
Fixed multiple console errors and warnings that were appearing in the browser console during application runtime.

## Issues Fixed

### 1. Calendar Sync 400 Bad Request Errors
**Problem:** Google Calendar and Teams Calendar sync functions were throwing 400 Bad Request errors on every page load.

**Root Cause:** The Edge Functions (`google-calendar-sync` and `teams-calendar-sync`) either don't exist or aren't properly configured, but the application was attempting to call them regardless.

**Solution:**
- Enhanced error handling in `Calendar.tsx` to gracefully handle missing or unconfigured calendar sync functions
- Added `console.debug()` logging instead of letting errors propagate to the console
- Only show success toast when at least one calendar successfully syncs
- Wrapped each calendar sync attempt in individual try-catch blocks

**Files Modified:**
- `src/pages/Calendar.tsx` (lines 76-123)

### 2. Case Data Fetch 406 Not Acceptable Error
**Problem:** GET request to `/rest/v1/cases?select=id%2Ctitle&id=eq.0a05ffaf-33c5-495c-9da2-a541c79f91d7` was returning 406 errors.

**Root Cause:** The `useDocuments` hook was attempting to fetch case information for documents that had a `case_id` in their metadata, but wasn't properly handling errors when:
- The case_id was invalid
- The case didn't exist
- The user didn't have permission to access the case
- The case_id wasn't a valid UUID string

**Solution:**
- Added type validation to ensure `case_id` is a string before querying
- Wrapped case queries in try-catch blocks
- Added error checking for the Supabase response
- Only attach case data if the query was successful and returned data
- Added debug logging for troubleshooting

**Files Modified:**
- `src/hooks/useDocuments.tsx` (lines 80-105, 124-149)

### 3. DOM Nesting Warning in TranscriptionsList
**Problem:** React warning: `validateDOMNesting(...): <div> cannot appear as a descendant of <p>`

**Root Cause:** The `CardDescription` component renders a `<p>` tag, but we were nesting `<div>` elements inside it, which is invalid HTML.

**Solution:**
- Replaced `CardDescription` with a plain `<div>` element
- Applied the same styling (`text-sm text-muted-foreground`) directly to the div
- Removed unused `CardDescription` import

**Files Modified:**
- `src/pages/TranscriptionsList.tsx` (lines 4, 109-125)

## Testing
All fixes have been applied and the application should now:
1. ✅ Not show calendar sync errors in the console
2. ✅ Gracefully handle missing or invalid case references
3. ✅ Have no DOM nesting warnings

## Impact
- **User Experience:** No visible changes to functionality
- **Developer Experience:** Cleaner console output, easier debugging
- **Performance:** Slightly improved due to better error handling
- **Reliability:** More robust error handling prevents cascading failures
